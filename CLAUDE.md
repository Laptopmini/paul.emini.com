# CLAUDE.md

Personal site + résumé for Paul-Valentin Mini (paul.emini.com), with an agent chat that renders résumé content as generative UI cards. The code is part of the portfolio: keep it clean.

**Everything not covered here is in `docs/IMPLEMENTATION_BRIEF.md`. Read it before starting a phase.** `docs/design/*.dc.html` are visual references only (custom runtime, `{{holes}}`); rebuild them as real React, never copy their markup.

## Stack and commands

- Next.js App Router, **static export** (`output: 'export'`), React 19, TypeScript strict. CSS Modules + CSS variables.
- pnpm workspace: root = site, `/worker` = Cloudflare Worker (CopilotKit runtime, MiniMax M3 via OpenRouter).
- `shared/agent.ts` is the tool contract between the Worker and the chat's card renderers. Change both sides together.
- The chat is headless CopilotKit. `next.config.ts` aliases CopilotKit's built-in UI packages (markdown, math, web components, inspector…) to an empty module to keep them out of the bundle. After upgrading CopilotKit, run `pnpm test:e2e`: a listed package that starts running at load time breaks the chat and must come off `UNUSED_CHAT_UI`.
- Landing-page client code imports plain values from `shared/constants.ts`, never `shared/agent.ts` or `@/content` (both pull zod into the bundle).
- Link preview and icons are generated at build (`app/og.png`, `app/icon.png`, `app/apple-icon.png`, colors read from `app/tokens.css`).
- Biome (lint + format), Vitest (unit), Playwright (e2e).

```sh
pnpm dev            # Next dev server
pnpm build          # static export to /out
pnpm check          # biome lint + format check
pnpm format         # biome format --write
pnpm typecheck      # tsc --noEmit
pnpm test           # vitest
pnpm test:content   # Zod validation of /content
pnpm test:e2e       # playwright (builds + serves /out)
pnpm test:evals     # agent evals on the real model, against a running `pnpm worker:dev` (~$0.02)
pnpm fetch:github   # refresh content/github.json (GITHUB_TOKEN=$(gh auth token) for the rate limit)
pnpm worker:dev     # Worker on :8787 with the real model (forwards only OPENROUTER_API_KEY from your env)
pnpm worker:mock    # Worker on :8787 with the scripted mock model (no keys)
```

Run `pnpm check && pnpm typecheck && pnpm test` before calling work done.

## /content is the single source of truth

- All résumé data lives in `/content` (typed JSON + md), validated by Zod schemas in `/content/schema`. Invalid content fails the build.
- UI cards **and** agent tools both read `/content`. Tools return ids/data; cards render it. Never hard-code titles, dates, quotes or copy that belongs in `/content` into components or prompts.
- `content/github.json` is generated by `scripts/fetch-github.ts` (daily Action `.github/workflows/github.yml`). Do not edit by hand. The site publishes it as `/github.json` and the Worker reads that copy (`GITHUB_DATA_URL`), so fresh activity needs no Worker deploy. Owned repos are limited to the curated projects' repos and `content/portfolio-repos.json` (never job-application or generated repos; a content test enforces it), each with its README's opening.
- Résumé updates come from `../my-resume` via the `/sync-resume` skill only.

## Color: the `--accent` rule

`--accent` is the **only** color value to change. Every accent shade (`--accent-strong`, `--accent-tint`, `--accent-ring`) is derived from it with `color-mix()`. Never write an accent hex anywhere else. Use tokens from `app/tokens.css` for every color; no raw hex in components.

## Privacy (hard rules)

- Never commit `resume.md` (raw or copied) from `../my-resume` into this repo.
- Never write the phone number anywhere in this repo (`/content`, components, prompts, tests, fixtures). It exists only inside `resume.pdf`.
- API keys are Worker secrets only. Never in the repo, `.env` files that get committed, or the client bundle.
- The Worker trusts nothing from the client but the messages and a persona id: `worker/src/sanitize.ts` rebuilds every run body, and `stream-filter.ts` keeps reasoning and provider errors out of the browser. Keep it that way.
- Guardrails (`worker/src/index.ts` → `guardedRun`): Turnstile-backed session, then the daily limits (`GuardState` Durable Object, visitors counted by a keyed hash of the IP, never the IP itself), then provider health, with the topic gate running alongside the model. Replies from guardrails are canned (`canned.ts`) and never call the model.
- The `dev` Wrangler environment holds public test values (Turnstile test secret, a throwaway session secret, `ALLOW_TEST_VISITOR`), so it must never be deployed; it has no URL on purpose.

## Interaction feedback and accessibility bar

Every interactive element gets visible feedback (~180ms transitions):
contact links lift 2px + shadow · prompt pills fill with ink on hover · cards rise 3px with stronger border + shadow · "View repo" arrow nudges up-right · buttons scale 0.96 on press, send scales 1.06 on hover · dock gets accent border + `--accent-ring` on `:focus-within` · `:focus-visible` = 3px accent outline, 3px offset. Springs (Motion) only for card enter/leave.

Accessibility is non-negotiable:
- Real `<button>`, `<a>`, `<label>`; icon-only controls have `aria-label`. Touch targets ≥ 44px.
- Text contrast ≥ 4.5:1. Persona toggle uses `aria-pressed`. Chat log is `aria-live="polite"`.
- Landing is fully server-rendered HTML (works with JS off).
- All motion disabled under `prefers-reduced-motion`.
- Lighthouse 95+ on every category for the landing page.
